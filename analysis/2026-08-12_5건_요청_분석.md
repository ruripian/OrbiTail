## 2. "프로젝트 전체 일정"을 개인 일정에서 제외

### 현황

`backend/apps/me/views.py:231` (`MeProjectEventsView`)

```python
.filter(project_id__in=member_project_ids)
.filter(Q(is_global=True) | Q(participants=user))
```

`is_global=True`(= "프로젝트 전체 일정" 토글 ON, **기본값 ON**)이면 참여자 지정 여부와 무관하게 내 캘린더에 들어옵니다. 이게 요청하신 증상입니다.

`ProjectEvent.is_global`의 기본값은 `True`이고(`models.py:228`, migration `0012`), `EventDialog`도 `useState(true)`로 시작합니다(`EventDialog.tsx:56`). 즉 **아무 생각 없이 만든 프로젝트 일정은 전부 전 멤버의 개인 캘린더에 들어갑니다.**

### 주의 — 같은 필터를 쓰는 곳이 하나 더 있습니다

`backend/apps/workspaces/views.py:1206` (팀 캘린더)도 `Q(is_global=True) | Q(participants__id__in=team_member_ids)`를 씁니다. 여기는 **팀 캘린더이므로 전체 일정이 보이는 게 맞습니다.** 건드리지 않는 걸 권합니다.

### 선택지

| 안 | 내용 | 결과 |
|---|---|---|
| **A (권장)** | `me/views.py` 필터를 `Q(participants=user)`로 축소 | 전체 일정은 개인 캘린더에서 완전히 사라짐. 프로젝트/팀 캘린더에서는 계속 보임 |
| B | 개인 캘린더에 "프로젝트 전체 일정 표시" 체크박스를 추가하고 기본 OFF (프론트 필터) | 사용자가 선택 가능. 대신 설정 UI가 늘고, 목록에는 계속 내려옴 |
| C | `is_global` 기본값을 `False`로 되돌림 | 신규 일정만 해결, 기존 일정은 그대로. 부작용 큼(팀 캘린더 노출도 같이 바뀜). **비권장** |

### 알아두실 트레이드오프 (A 선택 시)

전체 일정을 만들 때 **참여자를 지정하지 않으면 어떤 개인 캘린더에도 안 뜹니다.** 현재 `EventDialog`는 `is_global`과 `participants`를 각각 독립적으로 보내므로(`EventDialog.tsx:125,140`), 전체 일정 + 참여자 공란 조합이 실제로 만들어질 수 있습니다. 이건 의도된 동작(전체 일정 = 프로젝트 캘린더 전용)으로 보시면 되고, 필요하면 EventDialog 힌트 문구만 손보면 됩니다.

현재 문구: `"이 프로젝트에 참여하는 모든 멤버에게 해당되는 일정입니다"` → A 적용 후엔 `"프로젝트 캘린더에만 표시되고 개인 일정에는 들어가지 않습니다"` 같은 문구가 정확합니다.

## 3. 로그인 정보 저장

### 현황 — 요청 의도에 따라 답이 3가지로 갈립니다

| 항목 | 현재 상태 |
|---|---|
| 로그인 **유지** (새로고침/재방문 시 로그인 상태) | **이미 됨.** `authStore`가 zustand `persist`로 localStorage에 user/access/refresh 저장 |
| 세션 지속 기간 | access 60분 / refresh **7일**, rotation ON (`backend/config/settings/base.py:160-170`). 7일 이상 미접속 시 재로그인 필요 |
| **이메일 자동 채움** ("아이디 저장") | **없음.** LoginPage에 체크박스/저장 로직 없음 |
| 브라우저 비밀번호 관리자 연동 | **약함.** `LoginPage.tsx:83-105`의 Input에 `autoComplete` 속성이 없어 Chrome/Edge의 저장·자동완성이 잘 동작하지 않음 |

### 선택지 (복수 선택 가능)

- **(a) 아이디 저장 체크박스** — 로그인 성공 시 이메일만 localStorage 저장 → 다음 방문 시 폼에 자동 채움. 비밀번호는 저장 안 함. *구현 소형, 안전*
- **(b) `autoComplete` 속성 부여** — `autoComplete="username"` / `"current-password"`, form에 `name` 지정. 브라우저 자체 비밀번호 저장 프롬프트가 정상 작동. *한 줄짜리, 부작용 없음. 권장*
- **(c) 세션 기간 연장** — refresh 7일 → 30일 등. `.env`의 `JWT_REFRESH_TOKEN_LIFETIME_DAYS`만 바꾸면 되고 코드 변경 불필요. *보안 트레이드오프 있음*

### 결정 필요
**(a)/(b)/(c) 중 무엇을 원하시나요?** 저는 **(a)+(b)** 를 권합니다. (c)는 보안 정책 문제라 별도 판단이 필요합니다.

### (가) 앱 전역 UI 폰트 — 작업량 작음
