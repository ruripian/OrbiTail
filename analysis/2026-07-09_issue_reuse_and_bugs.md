## 1. 상태/우선순위 아이콘이 곳마다 다른 문제 (재사용 위반 — 최우선)

### 문제: 일부 소비처가 중앙 컴포넌트/상수를 안 쓰고 자체 렌더링

| 위치 | 파일:라인 | 우선순위 | 상태 | 판정 |

### 근본 원인
"이슈추가 다이얼로그"가 테이블이 쓰는 `PriorityPicker`/`StatePicker`(중앙 상수 기반)를 재사용하지 않고, 원시 `Select`에 **텍스트 라벨 / color dot만** 직접 그림. → 같은 데이터인데 화면마다 아이콘이 다르게 보임.

### 해결 방향 (재사용 원칙에 맞춤)
1. 이슈추가 다이얼로그의 우선순위/상태 입력을 테이블과 **동일한 `PriorityPicker`/`StatePicker` 컴포넌트로 교체**.
   - 이미 존재하는 컴포넌트라 신규 추상화 불필요(규칙 9 단순함 부합).
2. 만약 다이얼로그 폼 UX상 `Select` 유지가 필요하면, 최소한 SelectItem 내부에 `PriorityGlyph`/`getStateIcon`을 넣어 **아이콘 소스를 중앙 상수로 통일**.
3. 벌크 툴바 하드코딩 배열 → `PRIORITY_LIST`로 대체.
4. (구조적) 문서·이슈 공통으로 "우선순위 표시 1개 / 상태 표시 1개" 컴포넌트만 존재하도록 정리 — 새 화면은 반드시 이걸 import. 이게 5번 지적된 재사용 규칙의 실체.

## 3. 이슈 활동 로그에 상태값이 UUID로 나오는 문제

- **백엔드**: `backend/apps/issues/views.py:191, 197` (개별), `:1064`(벌크)
  - 상태 변경 시 `str(old.state_id)` / `str(updated.state_id)` — **UUID만 저장**. (제목/우선순위는 사람이 읽는 값인데 state만 ID)
- **프론트**: `ActivityTab.tsx:29, 32` — `old_value`/`new_value`를 그대로 출력 → "상태가 550e8400-... 에서 660e8400-... 로 변경" 처럼 보임.

### 해결 방향 (2가지)
- (A) **백엔드에서 저장 시 상태 이름을 넣기**: `old.state.name` / `updated.state.name` 저장. → 가장 단순, 기존 렌더링 그대로 사용.
  - 단점: 이미 쌓인 과거 로그는 여전히 UUID(마이그레이션 or 표시 시 폴백 필요).
- (B) 프론트에서 UUID→이름 매핑(states 목록 참조). 과거 로그도 커버되지만, states 로딩 의존.

> 권장: **(A) + 프론트 폴백**. 신규 로그는 이름 저장, 활동로그 렌더링 시 값이 UUID 형태면 states에서 이름 조회(재사용 유틸 1개). 이러면 과거/미래 로그 모두 해결.

## 4. 팀 캘린더 – "팀원 이벤트 안 보이고 내 것만" + "다른 팀원 해도 내 것이 남음"

### 데이터 흐름
- 프론트: `TeamCalendarSection.tsx:188-192` → `teamsApi.calendar.personalEvents(...)`
- 백엔드: `backend/apps/workspaces/views.py:1163`
  ```py
  qs = PersonalEvent.objects.filter(user=self.request.user, workspace=team.workspace)
  ```
  → **항상 요청자 본인 PE만** 반환 (teams.ts:53 주석에도 "본인 PE만"으로 명시됨).

### 버그 1 원인 — "팀원 이벤트 안 보임"
- 백엔드 필터가 `user=request.user`로 고정. 반면 **팀 이슈/프로젝트 이벤트는 `team_member_ids`로 팀원 전체 조회**(`views.py:1107-1118`).
- 즉 PersonalEvent만 팀 스코프가 아니라 개인 스코프. **UI는 "팀원 일정"처럼 보이지만 실제로는 본인 것만** → 설계 정책 불일치.

### 버그 2 원인 — "다른 팀원 해도 내 것이 종속적으로 남음"
- React Query 쿼리키 `["team", teamId, "personal-events", ...]`에 **사용자 식별자 없음** → 멤버 필터를 바꿔도 같은 캐시 재사용 + 응답 자체가 항상 request.user 기준이라 계속 내 이벤트만 표시.

### 해결 방향 (정책 결정 필요 — 아래 질문)
- (A) **팀원 PE 공개**: 백엔드 필터를 `user__in=team_member_ids` (+ 공개/비공개 정책: 공개=전체팀원, 비공개=팀장·본인)로 확장. 이슈 뷰와 동일 패턴 재사용. 멤버 필터 UI도 실제 동작.
- (B) **팀 캘린더에서 PE 비공개 유지**: 프론트에서 PE 멤버 필터 UI 제거/비활성화 + 주석 정정. (혼란만 제거, 기능 축소)

> 사용자 불만("팀원 이벤트가 안 보인다")로 볼 때 **(A) 공개 확장**을 원하시는 것으로 추정되나, 메모상 기존 정책이 "비공개=팀장·본인"이라 **명시적 확인 필요**.

## 5. 이슈 링크 기능

조사 결과 **코드상으로는 외부URL / 이슈-이슈(NodeLink) / 이슈-문서(양방향) 모두 백엔드·프론트 정상 구현·라우팅 완료** 상태입니다. 명백한 파손(엔드포인트 부재/필드 오타/데드코드)은 발견되지 않았습니다.

가능성 있는 실제 증상 후보(재현 정보 필요):
1. 링크 생성 후 즉시 화면 반영 안 됨 → `GraphView`/상세의 query invalidation 타이밍.
2. `blocked_by/duplicates/references`는 **의도적으로 프론트에서 "연결/의존" 2종만** 노출(설계 제한). 이걸 "안 된다"로 느끼셨을 수 있음.
3. 이슈↔문서 링크가 이슈 사이드바 vs 문서 쪽에서 **표시 위치/워딩이 달라** 양방향 인지가 어려움 (이것도 재사용/워딩 통일 이슈).

> 정확한 진단을 위해 **어떤 링크에서 무엇이 안 되는지(생성 실패/미표시/워딩)** 를 알려주시면 해당 경로를 바로 파고들겠습니다.
