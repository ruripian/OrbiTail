# 문서 탐색기를 파일 시스템처럼 — 실사 및 설계

작성일: 2026-08-19 / 대상: `frontend/src/pages/documents/DocumentExplorerPage.tsx`
질문: "시놀로지 NAS / 윈도우 탐색기처럼 폴더·문서를 드래그앤드롭으로 옮기는 게 가능한가?"

## 0. 결론 먼저

**가능하고, 절반은 이미 만들어져 있습니다.** 다만 만들어져 있는 쪽은 **사이드바 트리**이고,
정작 탐색기 화면에는 **드래그앤드롭이 한 줄도 없습니다.**

---

## 1. 실사 결과

### 1-1. 사이드바 트리 — DnD 구현되어 있음
`components/layout/DocumentLayout.tsx`
- `draggable` + `onDragStart/onDragOver/onDrop` (610~660행)
- 드롭 위치 3종: `before` / `inside` / `after` — 폴더 안에 넣기 + 형제 사이 순서 재배치 모두 지원
- `wouldCreateCycle()` 로 자기 자신·자손에 넣는 순환 차단
- 사이드바 하단 "최상위로 빼기" 드롭 존
- 순서는 `sort_order` 를 이웃 값의 중간값으로 계산해 부여(재정렬 비용 없음)

→ **파일 시스템식 조작의 핵심 로직은 이미 검증돼 돌아가고 있습니다.**

### 1-2. 탐색기 화면 — DnD 없음 (문서와 코드 불일치)
`DocumentExplorerPage.tsx` 상단 주석:
```
 * 문서 탐색기 — 윈도우 탐색기 스타일 파일/폴더 관리.
 * 그리드/목록 전환, 드래그앤드롭 이동, 우클릭 컨텍스트 메뉴.
```
실제 코드(286행 전체)에 `draggable` · `onDrop` · `onDragOver` · `onContextMenu` **0건**.
주석이 구현되지 않은 계획을 서술하고 있습니다.

### 1-3. 그 밖에 발견한 결함 (같은 파일)

| 위치 | 문제 |
|---|---|
| `ItemMenu` 의 "이름 변경" | `onClick` 이 없음 — **클릭해도 아무 일도 일어나지 않는 죽은 메뉴** |
| `ItemMenu` 의 "이동" | 같음. 죽은 메뉴 |
| 그리드 항목 | `onClick` 과 `onDoubleClick` 이 **둘 다 열기** — 단일 클릭에 이미 열려서 더블클릭이 무의미. 탐색기식이라면 단일=선택 / 더블=열기 |
| 전반 | **선택(selection) 상태 개념이 없음** — 다중 선택·일괄 작업의 토대가 없음 |

### 1-4. 백엔드
- 이동 API 있음: `POST /docs/<id>/move/` → `{ parent, sort_order }` (단건)
- **일괄 이동 API 없음** — 다중 선택 이동은 N번 호출하거나 벌크 엔드포인트 신설 필요

## 3. 먼저 정리해야 할 전제 — "문서 시스템"과 "파일 시스템"의 차이

OrbiTail 문서는 **파일 저장소가 아니라 문서 트리**입니다.

- 노드는 `Document` 하나뿐이고 `is_folder` 플래그로 폴더/문서를 구분합니다
- 실제 파일(첨부)은 **문서 안에만** 존재합니다(`DocumentAttachment`). 폴더에 파일을 둘 수 없습니다
- 그래서 **OS에서 PDF/이미지를 끌어다 폴더에 놓는 것**(#12)은 지금 모델로는 불가능합니다.
  하려면 "첨부만 담는 문서를 자동 생성" 같은 우회가 필요하고, 이건 문서 시스템의 성격을 바꾸는 결정입니다.

**#12를 뺀 나머지(#1~11)는 모두 지금 모델 그대로 구현 가능합니다.**

## 4. 단계별 설계

### 1단계 — 탐색기에 드래그앤드롭 (사이드바 로직 재사용)
- 그리드/목록 항목에 `draggable` + `dataTransfer("doc-id")`
- 드롭 대상: **폴더 항목**(안으로 넣기), **브레드크럼 각 단계**(상위로 빼기), **빈 배경**(현재 폴더로)
- 순환 차단은 기존 `wouldCreateCycle()` 을 공용 유틸로 옮겨 양쪽이 같이 사용
- 드래그 중 폴더 테두리 하이라이트 + 드롭 불가 대상은 커서로 구분

> 재사용 지점: 이동 계산(부모 변경 / sort_order 중간값)을 `lib/document-tree.ts` 로 추출하면
> 사이드바·탐색기가 같은 규칙을 쓰게 됩니다. 지금은 사이드바 컴포넌트 안에 인라인으로 들어 있습니다.

### 2단계 — 선택 모델 + 다중 이동
- `selectedIds: Set<string>` 상태. 클릭=단독 선택, Ctrl+클릭=토글, Shift+클릭=범위
- 그리드 항목의 단일클릭/더블클릭 역할 분리(단일=선택, 더블=열기) — **1-3의 결함도 여기서 해소**
- 선택된 여러 개를 한 번에 드래그
- 백엔드: `POST /spaces/<id>/docs/bulk-move/` `{ ids: [], parent, sort_order? }` 신설 권장
  (N번 호출하면 중간 실패 시 일부만 옮겨진 상태가 남습니다)

### 3단계 — 탐색기 조작감
- 우클릭 컨텍스트 메뉴(열기 / 새 탭 / 이름 변경 / 이동 / 삭제 / 새 폴더)
- **죽은 메뉴 2개(이름 변경·이동) 실제 동작 연결** — 이건 1단계와 함께 고쳐도 됩니다
- 키보드: 방향키 이동, Enter 열기, F2 이름 변경, Delete 삭제, Ctrl+A 전체 선택
- 잘라내기/붙여넣기(Ctrl+X/V) — 선택 모델이 있으면 이동 API 재사용으로 간단

### 4단계 (선택) — 되돌리기
- 이동 직후 토스트에 "실행 취소" — 이전 `parent`/`sort_order` 를 기억했다가 되돌림
- 파일 시스템식 조작에서 오조작이 잦아 체감 효용이 큽니다

## 5. 기술 선택 — 라이브러리 없이 가능

- 현재 사이드바가 **HTML5 native DnD**(`draggable` + `dataTransfer`)로 동작합니다.
  탐색기도 같은 방식이면 **새 라이브러리 설치가 필요 없습니다.**
- 다만 native DnD 의 한계가 있습니다:
  - 드래그 고스트 이미지 커스터마이즈가 제한적(여러 개를 끌 때 "3개 항목" 배지 같은 표현)
  - 터치 기기 미지원
- 이 둘이 꼭 필요하면 `dnd-kit` 같은 포인터 기반 라이브러리가 필요하고, **설치 허락을 받아야 합니다.**
  현재 요구(마우스로 옮기기)만 보면 native 로 충분합니다.

## 8. 구현 결과 (2026-08-19)

### 공용 규칙 추출 — `frontend/src/lib/document-tree.ts` (신규)
사이드바에 인라인으로 있던 로직을 꺼내 두 화면이 같은 규칙을 쓰게 했다.
- `buildChildrenMap()` / `wouldCreateCycle()` — 순환 차단(BFS, 방문 노드 스킵)
- `sortExplorerItems()` — **폴더 먼저 → sort_order → 제목** 순
- `calcInsertOrder()` / `calcAppendOrder()` — 이웃 중간값으로 순서 부여(전체 재정렬 없음)

사이드바 트리(`DocumentLayout`)의 루트·자식 정렬도 `sortExplorerItems` 로 바꿔 두 화면의 순서를 일치시켰다.
**정렬이 다르면 사이드바에서 옮긴 결과가 탐색기에서는 엉뚱한 자리처럼 보인다.**

### 백엔드 — `DocumentBulkMoveView` (마이그레이션 없음)
`POST /spaces/<id>/docs/bulk-move/` `{ ids: [], parent: id|null }`
- **순환 검사를 전부 통과한 뒤에만 저장** — 한 건씩 N번 호출하면 중간 실패 시 일부만 옮겨진 상태가 남는다
- 끌어온 순서를 유지하려고 쿼리 결과가 아니라 **요청 `ids` 순서**로 `sort_order` 를 매긴다
- 권한: `_check_space_edit`(EDITOR+)

### 프론트 — 탐색기 재작성
| 기능 | 내용 |
|---|---|
| 선택 | `selected: Set`. 클릭=단독, Ctrl/Cmd+클릭=토글, Shift+클릭=범위(현재 보이는 순서 기준) |
| 클릭 | **단일=선택 / 더블=열기** (기존엔 둘 다 열기라 더블클릭이 무의미했다) |
| 드래그 | 항목 `draggable`, `dataTransfer("doc-ids")` 로 **여러 개를 함께** 전달. 선택 밖 항목을 끌면 그것만 끌려간다(윈도우와 동일) |
| 드롭 대상 | 폴더 항목 / 브레드크럼 각 단계(상위로 빼기) / 빈 배경(현재 폴더) |
| 시각 | 드롭 대상 ring 하이라이트, 선택 항목 강조, 잘라낸 항목 반투명 |
| 우클릭 | 커서 위치 컨텍스트 메뉴 — 열기·이름변경·잘라내기·붙여넣기·새 폴더·삭제 (빈 배경에서는 붙여넣기/새 폴더) |
| 키보드 | Ctrl+A 전체선택, Ctrl+X 잘라내기, Ctrl+V 붙여넣기, F2 이름변경, Delete 삭제, Enter 열기, Esc 해제 |
| 이름 변경 | 인라인 입력(Enter 확정 / Esc 취소) |

**1-3의 죽은 메뉴 2개를 실제 동작에 연결했다** — "이름 변경"은 인라인 편집, "이동"은 잘라내기로.

키보드 핸들러는 `INPUT`/`TEXTAREA` 포커스와 이름 변경 중에는 빠져나가, 문서 편집 단축키와 겹치지 않는다.

### 검증 (실데이터, 트리 A > B > C 구성 후 정리)
1. 단건 이동: 문서D → 폴더A `{moved: 1}`, 부모 반영 확인
2. **순환 차단**: 폴더A를 그 자손인 폴더B로 이동 시도 → **400**, A의 부모는 그대로 유지
3. 다중 이동: C·D를 한 번에 최상위로 `{moved: 2}`, **요청 순서대로 sort_order 부여**(65536 < 65537)
4. `manage.py check` 이상 없음, 프론트 `npm run build`(tsc strict) 통과

## 9. 이동 경로 확장 (같은 날 추가)

"이동할 때 상위로 보내는 팝업 vs 화면 분할" 논의 결과 — **사이드바 드롭(C) + 화면 분할(B) 둘 다** 채택.
우측 하단 팝업(A)은 브레드크럼 드롭과 기능이 겹쳐 제외했다.

### C. 사이드바 트리로 드롭
두 화면이 서로 다른 드래그 키를 써서 상호 드롭이 아예 불가능했다.
| | 변경 전 | 변경 후 |
|---|---|---|
| 사이드바 | `doc-id` (단수 문자열) | `doc-ids` (JSON 배열) |
| 탐색기 | `doc-ids` (JSON 배열) | 동일 |

- `readDocIds()` 헬퍼로 페이로드 읽기를 통일
- `TreeNode.onMove` 시그니처를 `(docIds: string[], …)` 로 확장
  - `inside` → `bulkMove`, 순환은 **하나라도 걸리면 전부 취소**
  - `before`/`after` → 한 개면 `calcInsertOrder` 로 정확한 자리, 여러 개면 순서가 모호하므로 같은 부모 뒤에 붙임
- 사이드바 "최상위로 빼기" 드롭 존도 다중 수용

→ 탐색기에서 여러 개를 골라 사이드바의 **아무 폴더에나** 놓을 수 있다. 화면 분할 없이 임의 위치 이동이 가능해졌다.

### B. 화면 분할
`components/documents/ExplorerPanel.tsx` 로 패널을 추출하고 페이지는 배치만 맡는다.
- 패널마다 **독립**: 경로(브레드크럼)·선택·뷰 모드·러버밴드·우클릭 메뉴
- 패널 밖(페이지)에 둔 것: **클립보드**(한쪽에서 잘라 다른 쪽에 붙여넣는 게 분할의 핵심 용도), 라벨 필터, 문서 목록 쿼리
- 키보드 단축키는 **활성 패널에만** 적용. 활성 패널은 ring 으로 표시
- 분할 시 그리드 열 수를 줄여 좁아진 폭에 맞춘다
- 다른 곳에서 현재 폴더가 삭제되면 루트로 되돌린다(경로가 허공을 가리키는 상태 방지)

### 남은 것
- 4단계 되돌리기(Undo) — 미착수
- OS 파일 드롭 업로드 — 모델 변경이 필요해 범위 밖
- native DnD 한계: 여러 개를 끌 때 "3개 항목" 같은 커스텀 고스트 없음, 터치 미지원
  (필요해지면 `dnd-kit` 설치 논의)
