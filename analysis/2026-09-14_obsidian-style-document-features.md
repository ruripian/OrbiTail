# 문서 기능 — Obsidian 스타일 편의성 분석 및 방향 설정

작성일: 2026-09-14
선행 문서: `2026-08-19_tier3-document-features.md`, `2026-08-19_document-space-settings-gap.md`

## 0. 먼저 — "Obsidian 편의성"을 무엇으로 볼 것인가

Obsidian이 편하다고 할 때 실제로 가리키는 것은 대개 이 다섯 묶음이다.
이 분류를 기준으로 현황을 재고, 방향을 정한다.

| 묶음 | 구체 기능 |
|---|---|
| **링크·그래프** | `[[위키링크]]`, 자동완성, 없는 문서면 생성, **백링크 패널**, 미연결 언급(unlinked mentions), 그래프 뷰(전역/로컬), 깨진 링크 탐지, 문서 이름 변경 시 링크 자동 갱신 |
| **탐색·조작** | 퀵 스위처(Ctrl+O), 커맨드 팔레트(Ctrl+P), 연산자 검색(`tag:`, `path:`, `file:`), 링크 **호버 프리뷰**, 탭·분할 화면, 아웃라인 패널 |
| **편집** | 마크다운 그대로 입력·라이브 프리뷰, 소스 모드 전환, 콜아웃, 문서/블록 **임베드**(`![[문서#제목]]`, `^블록ID`), 각주, LaTeX, Mermaid |
| **메타데이터** | YAML 프로퍼티(frontmatter), 인라인 `#태그` + 태그 패널, 별칭(alias), 데이터뷰(쿼리 기반 목록) |
| **파일·보관** | 평문 `.md` 볼트, 폴더 = 트리, 데일리 노트, 템플릿, 캔버스 |

## 1. 현황 — 이미 있는 것이 생각보다 많다

새로 만들 것을 논하기 전에, 착각을 먼저 제거한다.

| Obsidian 기능 | OrbiTail 현황 | 위치 |
|---|---|---|
| 문서 링크(멘션) | **있음.** `#`로 문서, `@`로 사용자, `$`로 이슈 자동완성 | `DocumentEditor.tsx:1566,1604` |
| `[[문서]]` 표기 | **표시만 있음.** 문서 멘션이 `[[라벨]]`로 렌더될 뿐, `[[`는 입력 트리거가 아니다 | `DocumentEditor.tsx:885` |
| 콜아웃 | **있음.** info/success/warning/danger 4종, 슬래시 메뉴 | `DocumentEditor.tsx:556` |
| 슬래시 커맨드 | **있음.** 카테고리·키워드 검색 | `DocumentEditor.tsx:1400~` |
| 퀵 스위처 | **있음.** `Ctrl/Cmd+K`, 문서 모드 자동 인식 | `TopBar.tsx:88`, `CommandSearchDialog.tsx` |
| 연산자 검색 | **부분.** 이슈용 `priority:` `status:` `assignee:me`만. 문서는 `q`·`labels`뿐 | `CommandSearchDialog.tsx:26`, `views.py:687` |
| 아웃라인(목차) | **있음.** 우측 패널, 폭 저장 | `DocumentSpacePage.tsx:1067` |
| 태그 | **라벨로 있음.** 워크스페이스 단위 M2M, 색상, 탐색기 필터 | `models.py DocumentLabel` |
| 템플릿 | **있음.** built_in/user/workspace/space 4범위 | `models.py DocumentTemplate` |
| LaTeX·Mermaid | **있음.** katex + mermaid | `DocumentEditor.tsx:7~10` |
| 폴더 트리 | **있음.** `parent` FK + 드래그 정렬 | `models.py Document` |
| 호버 프리뷰 | **이슈만 있음.** 문서 멘션에는 없음 | `DocumentEditor.tsx:799` |
| 버전 이력 | **있음** (Obsidian 무료판보다 나음) | `DocumentVersion` |
| 블록 댓글 | **있음** (Obsidian에 없음) | `CommentThread` |

> 즉 **편집 경험 쪽은 이미 Obsidian과 대등하거나 앞선다.**
> 빠진 것은 거의 전부 **"링크를 데이터로 다루는 층"**과 **"마크다운 상호운용"** 두 곳에 몰려 있다.

## 2. 구조적 간극 — 세 가지, 그중 하나가 핵심

### 간극 A. 링크가 데이터가 아니다 ★ 이것이 병목

문서 멘션은 `content_html` 안의 `<span data-mention data-kind="doc" data-id="...">`로만 존재한다.
**링크를 담은 테이블이 없다.** `DocumentIssueLink`(문서↔이슈)는 있지만 **문서↔문서는 없다.**

그래서 아래가 전부 불가능하다 — 개별 기능이 어려운 게 아니라, **한 개의 빠진 테이블 때문에 한꺼번에 막혀 있다.**

- 백링크 패널 ("이 문서를 가리키는 문서들")
- 문서 그래프 뷰
- 깨진 링크 탐지 (가리키던 문서가 삭제·휴지통행)
- 문서 제목 변경 시 링크 표시 갱신 (지금은 `data-label`이 **박제**되어 옛 제목이 계속 보인다)
- 미연결 언급 (제목이 본문에 평문으로 등장하는 곳 찾기)

### 간극 B. 소스가 마크다운이 아니다

저장 형식은 `content_html`(TEXT) + `yjs_state`(BINARY)다. Obsidian은 평문 `.md`다.

- 내보내기는 HTML zip이다 (`SpaceExportView`). `.md` 반출이 없다.
- `.md` 반입이 없다. 기존 Obsidian 볼트를 가져올 수 없다.
- 프론트에 마크다운 파서/시리얼라이저 의존성이 **하나도 없다** (`turndown`/`marked`/`remark` 모두 미설치).

단, StarterKit의 입력 규칙 덕에 **타이핑 경험은 이미 마크다운스럽다**(`# `, `- `, `> `, ``` ). 없는 것은 **파일 수준 상호운용**이다.

### 간극 C. 볼트가 아니라 권한 스페이스다

Obsidian은 1인 로컬 볼트라 "전역 그래프"가 자명하다. OrbiTail은 스페이스마다 권한이 다르다
(`_space_role()` / VIEWER·EDITOR·ADMIN). 따라서 **그래프·백링크는 반드시 "내가 볼 수 있는 스페이스"로 잘려야 한다.**

이건 제약이자 설계 요구사항이다. 조용히 넘기면 **권한 유출이 된다** — 볼 수 없는 문서의 제목이 백링크 목록에 뜨는 식으로.
반대로 "가리키는 문서가 N개 더 있지만 볼 수 없음" 같은 **가려진 사실의 명시**는 필요하다.

|---|---|---|---|

| 데일리 노트 | 쉬움 | 소 | 템플릿 + 날짜 제목 규칙. 협업 도구에서 효용은 낮음 |

| 캔버스 | **범위 밖** | 대 | 별도 제품 기능 |
| 탭·분할 화면 | 중간 | 중 | 라우팅·레이아웃 전반 변경. 효용 대비 파급 큼 |

## 4. 키스톤 — `DocumentLink` 테이블

위 표에서 "중간" 대부분이 **이 하나에 종속**된다. 먼저 놓지 않으면 나머지가 전부 임시방편이 된다.

```python
class DocumentLink(models.Model):
    """문서 → 문서 참조. content_html 저장 시 파싱해 재구축한다.

    DocumentIssueLink(문서↔이슈)와 나란한 자리. 그쪽은 사용자가 명시적으로 거는 연결이고,
    이쪽은 본문에서 파생되는 연결이라 저장 때마다 통째로 갈아끼운다.
    """
    source = FK(Document, related_name="outgoing_links", on_delete=CASCADE)
    target = FK(Document, related_name="incoming_links", on_delete=CASCADE)
    created_at = DateTimeField(auto_now_add=True)

    class Meta:
        db_table = "document_links"
        unique_together = [("source", "target")]
        indexes = [Index(fields=["target"])]   # 백링크 조회가 주 경로
```

**갱신 지점**: `DocumentDetailView.update()` + Yjs 저장 경로(`yroom.py`) — 두 곳 모두에서
`content_html`의 `data-kind="doc"` 멘션을 파싱해 **delete-all + bulk_create**. 증분 diff는 불필요한 복잡도다.

**주의**:
- Yjs 실시간 저장은 **잦다.** 링크 재구축을 매 저장마다 돌리면 쓰기 부하가 붙는다
  → 파싱 결과 해시를 비교해 **변화 없으면 건너뛴다**(간단하고 효과 확실).
- 삭제/휴지통 문서로의 링크는 **행을 남긴 채** 프론트에서 "깨진 링크"로 표시. 지우면 탐지가 불가능해진다.
- 백링크 조회는 **반드시 `_get_accessible_spaces()`로 필터**. 안 하면 권한 유출(간극 C).

**이것 하나가 여는 것**: 백링크 · 그래프 · 깨진 링크 · 제목 갱신 · 문서 임베드 · "이 문서를 지우면 N곳이 깨집니다" 경고.

## 5. 결정이 필요한 충돌 — 3건

### 충돌 1. `#`를 누가 갖는가 ★ 가장 먼저 합의할 것

- 현재: `#` = **문서 링크** 트리거 (`DocumentEditor.tsx:1604`)
- Obsidian: `#` = **태그**, `[[` = 문서 링크

선택지:

| 안 | 내용 | 대가 |
|---|---|---|
| **A. Obsidian 정렬** | `[[` → 문서, `#` → 태그로 **교체** | 기존 사용자의 손버릇이 깨진다. 기존 문서의 `#` 멘션은 이미 노드로 저장돼 있어 **데이터는 안전**하나, 앞으로의 입력만 달라진다 |
| **B. 공존** | `[[`를 **추가**하고 `#`는 문서 링크로 유지. 태그는 라벨 UI로 | 학습 비용 없음. 다만 Obsidian 사용자가 `#태그`를 치면 문서 팝업이 떠서 어리둥절 |
| **C. 공존 + 태그는 다른 문자** | `[[` 문서, `#` 문서(유지), 태그는 라벨 피커만 | 인라인 태그를 포기 |

> 권장: **B**. `[[` 추가는 비용이 거의 없고 즉시 체감되며, 기존 동작을 깨지 않는다.
> 인라인 태그는 충돌 2와 함께 판단한다.

### 충돌 2. 라벨 vs 태그 — 둘 다 둘 것인가

`DocumentLabel`은 이미 워크스페이스 단위 분류축이고 색·관리 UI·검색 필터까지 붙어 있다.
Obsidian 인라인 `#태그`를 별도로 도입하면 **분류축이 둘**이 된다. 이건 거의 항상 나쁜 결말이다.

> 권장: **라벨 하나로 유지.** 인라인 태그가 정말 필요하면 "본문에서 `#`로 친 것이 곧 라벨"이 되게
> **같은 테이블에 흡수**해야지, 평행 개념을 만들면 안 된다. (Tier3 문서에서 이슈 Label을 재사용하지 않기로 한 판단과 같은 논리다.)

### 충돌 3. 프로퍼티(frontmatter)를 도입할 것인가

Obsidian 프로퍼티 = 문서별 임의 key-value. OrbiTail에는 `labels` + 고정 필드(폭·글자크기·커버)가 있다.
임의 key-value를 열면 **데이터뷰 없이는 쓸모가 적고**, 데이터뷰는 범위 밖이다.

> 권장: **보류.** 링크 층을 먼저 세우고, 그다음에 필요가 실제로 드러나면 착수.

## 6. 방향 3안

### A안 — 지식베이스화 (링크·그래프 중심)
`DocumentLink` → 백링크 패널 → 깨진 링크 → 문서 그래프 → 문서 임베드.
**얻는 것**: Obsidian의 정체성 그 자체. 문서가 쌓일수록 가치가 커진다.
**비용**: 중. **위험**: 그래프 뷰 일반화, Yjs 저장 부하.

### B안 — 마크다운 상호운용 (반입·반출 중심)
`.md` 반출 → `.md` 반입 → 볼트 폴더 구조·`[[링크]]` 해석.
**얻는 것**: 기존 Obsidian 사용자를 그대로 데려온다. 잠금(lock-in) 불안 해소.
**비용**: 중. **위험**: 커스텀 노드(콜아웃·이슈 임베드·이슈뷰)의 마크다운 표현을 **무손실로 못 한다** — 손실 범위를 먼저 합의해야 한다.

### C안 — 조작 속도 (탐색·입력 중심)
`[[` 트리거 → 없는 문서 즉석 생성 → 호버 프리뷰 → 연산자 검색(`tag:` `space:` `title:`).
**얻는 것**: 항목마다 비용이 작고 **당장 체감된다.** 위험이 거의 없다.
**비용**: 소. **위험**: 낮음. 단, 구조적 간극은 그대로 남는다.

## 7. 권장 — C → A → B 순

| 단계 | 내용 | 이유 |
|---|---|---|
| **1** | **C안 전부** (`[[` 트리거, 즉석 생성, 호버 프리뷰, 연산자 검색) | 며칠 규모. 즉시 체감. 되돌릴 일이 없다. 여기서 "이게 원하던 것"인지 판단이 선다 |
| **2** | **`DocumentLink` + 백링크 패널 + 깨진 링크** | 키스톤. 이후 모든 것의 전제 |
| **3** | 문서 그래프 뷰 | `GraphView` 일반화 비용을 2단계 결과를 보고 판단 |
| **4** | `.md` 반출 → 반입 | 손실 범위 합의가 선행돼야 함 |
| **보류** | 프로퍼티, 인라인 태그, 데이터뷰, 캔버스, 탭·분할 | 5장·3장 참조 |

**1단계와 2단계는 서로 간섭하지 않는다** (한쪽은 에디터 입력, 한쪽은 모델·API).

## 8. 검증 기준

**1단계**
1. `[[`를 치면 문서 자동완성이 뜨고, 기존 `#`도 그대로 동작한다
2. 없는 제목을 입력하면 "새 문서 만들기"가 뜨고, 선택 시 문서가 생성되며 링크가 그 문서를 가리킨다
3. 문서 멘션에 마우스를 올리면 제목·경로·앞부분 미리보기가 뜬다
4. 검색창에 `space:정책 title:회의`를 넣으면 해당 조건만 반환된다

**2단계**
1. A가 B를 링크 → B의 백링크 패널에 A가 뜬다. 링크를 지우면 사라진다
2. B를 휴지통에 보내면 A의 링크가 "깨짐"으로 표시되고, 복원하면 되돌아온다
3. 접근 권한 없는 스페이스의 문서는 백링크 목록에 **제목조차 노출되지 않는다**
4. 같은 문서를 연속 20회 저장해도 링크 테이블 쓰기가 1회만 발생한다(해시 스킵)
5. `manage.py check` 통과, `npm run build` 통과

### 인라인 `#태그` — 라벨에 흡수

5장 충돌 1·2의 결론을 지켰다. **`#` 팝업이 태그와 문서를 함께 보여준다.**

- `#` → 태그(위) + 문서(아래) + "새 태그로 만들어 붙이기". Obsidian 손버릇과 기존 손버릇이 모두 통한다
- `[[` → 문서만. 정확히 문서를 걸고 싶을 때
- 태그를 고르면 본문에 칩이 박히고 **같은 라벨이 문서에도 붙는다**(기존 `DocumentLabel` 그대로 — 분류축을 늘리지 않음)
- 태그 칩을 누르면 그 태그로 거른 탐색기로 간다. 그래서 탐색기 라벨 필터를 URL(`?labels=`)로 옮겼다 — 걸러 놓은 화면을 공유할 수도 있게 됐다
- 이름·색은 박아 두지 않고 라벨 목록에서 찾아 그린다 → 라벨을 고치면 본문 태그도 따라온다

**본문을 라벨의 원본으로 삼지 않았다.** 그렇게 하면 라벨 피커로 붙인 라벨이 저장할 때마다 지워진다.
본문에서 태그를 지워도 라벨은 남고, 해제는 제목 아래 라벨 줄에서 한다.

### 4단계 — `.md` 반출·반입

`apps/documents/markdown.py` 하나에 양방향을 모아 뒀다. **변환 라이브러리를 들이지 않았다** —
읽고 쓰는 대상이 우리 에디터가 찍어낸 HTML 과 Obsidian 볼트로 정해져 있고, 어차피 특별 취급해야 하는
콜아웃·멘션·이슈 카드는 범용 변환기가 해 주지 않는다. 표준 `html.parser` 로 충분했다.

손실 처리(합의안 그대로):

| 노드 | 마크다운 |
|---|---|
| 콜아웃 | `> [!warning]` (Obsidian 문법). 반입 시 `tip`→success, `note`→info 등으로 매핑 |
| 문서 멘션 | `[[제목]]<!--orbitail:doc id="..."-->` — 다른 앱에선 그냥 위키링크, 우리 쪽으로 돌아오면 원래 문서로 복원 |
| 태그 멘션 | `#태그` |
| 이슈 카드 | `<!--orbitail:issue id="..." identifier="..."-->` + 표시용 글자 |
| 수식 | `$인라인$` / `$$블록$$` · Mermaid → ```` ```mermaid ```` |

**반출**: 문서 한 장(`/docs/<id>/export-md/`) + 스페이스 zip(`/export/?type=md`).
머리말에 `title`·`orbitail-id`·`tags`(라벨)·`created`/`updated`·사용자 프로퍼티가 나간다.
마크다운 묶음의 목차도 `index.md` 로 낸다 — `.md` 사이에 HTML 목차를 끼우면 볼트에 이물질이 섞인다.

**반입**: `/spaces/<id>/import/` 에 `.md` 한 장 또는 볼트 `.zip`.
폴더 구조 → 문서 트리, 머리말 → 프로퍼티, `tags:` → 라벨(같은 이름이면 기존 라벨 재사용),
`[[링크]]` → 문서 멘션. **위키링크는 모든 문서를 만든 뒤 2차로 잇는다** — 한 번에 하면 아직
안 만들어진 문서를 가리키는 링크가 전부 끊긴 채 들어온다. 볼트는 서로 가리키는 게 정상이라 그 손실이 크다.

"md 렌더러가 없다"로 처리된다. `?type=md` 로 바꿨다.
