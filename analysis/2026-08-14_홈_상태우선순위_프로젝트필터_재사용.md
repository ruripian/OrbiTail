## 0. 전제 확인 (틀리면 알려주세요)

"이슈의 홈 페이지 = 기본 페이지" 를 **워크스페이스 홈 `/:ws` (`WorkspaceDashboard.tsx`)** 로 해석했습니다.

근거:
- 프로젝트 필터를 가진 이슈 목록 화면은 홈 / 마이 캘린더 / 마이 그래프 3곳뿐이고, 그중 "기본 페이지(index 라우트)"는 홈입니다 (`router/index.tsx:213`).
- 프로젝트 이슈 페이지(`TableView`/`TimelineView`)는 이미 `StatePicker`/`PriorityPicker` 를 재사용 중이라 "다르다"는 지적과 맞지 않습니다.
- 홈의 `IssueRow` 는 `/:ws/recent`(RecentIssuesPage)에서도 그대로 재사용되므로, 홈을 고치면 최근 이슈 페이지도 함께 정리됩니다.

## 2. 홈 페이지가 표준에서 벗어난 지점 (4건)

### A. 그룹 헤더가 상태 아이콘을 쓰지 않음 — `WorkspaceDashboard.tsx:154`

```tsx
<Circle className="h-4 w-4 shrink-0" style={{ color: g.color, fill: g.color }} />
```

`getStateIcon(group)` 을 쓰면 backlog=점선원 / unstarted=빈원 / started=중심점원 으로 구분되는데, 홈은 **전부 채워진 원**입니다. 테이블·타임라인·문서 이슈 피커에서 익힌 "모양 = 진행 단계" 규칙이 홈에서만 무너집니다.
문제는 `IssueGroup` 타입(`:90`)이 `key/label/color` 만 들고 있어 **group 값을 아예 버리고 있다**는 점입니다(`groups` useMemo `:259`). 데이터는 `issue.state_detail.group` 에 이미 있습니다.

### B. 상태 필터가 자체 색/라벨 테이블을 들고 있음 — `:34-43`

```tsx
const STATE_GROUP_LABEL = { backlog: "Backlog", unstarted: "To do", started: "In progress" };
const STATE_GROUP_COLOR = { backlog: "#94a3b8", unstarted: "#64748b", started: "#3b82f6" };
```

- 색: `tokens.css` 의 `--state-{group}-border` 와 무관한 4번째 하드코딩 세트입니다
  (① tokens.css ② GraphView `STATE_COLOR:60` ③ 홈 `STATE_GROUP_COLOR` ④ DB `state.color`).
- 라벨: 영문 하드코딩 + i18n 미적용. 게다가 `unstarted` 를 홈은 "To do", StatesPage는 "Unstarted" 로 부릅니다.
- 형태: 2px 원형 dot — 상태 아이콘이 아닙니다.

### C. `IssueRow` 에 상태 표시가 전혀 없음 — `:109-145`

홈 좌측은 상태별로 그룹핑돼 있어 행에 상태가 없어도 되지만, **같은 `IssueRow` 를 쓰는 우측 "최근 이슈" 위젯(`:483`)과 `/:ws/recent` 전체 페이지에는 그룹 헤더가 없습니다.** 결과적으로 그 두 곳에서는 이슈의 상태를 알 방법이 없습니다.
반면 성격이 같은 `IssuePickerDialog` 행은 `StateIcon + PriorityGlyph + 식별자 + 제목` 순서로 렌더합니다 — 사실상 이것이 "이슈 한 줄" 표준입니다.

### D. 읽기 전용 칩 표준(`StateChip`/`PriorityChip`)이 고립돼 있음

`chips/` 는 ArchiveView·TrashView 두 곳에서만 쓰입니다. 홈은 `PriorityGlyph` 를 직접 부르고 `title` 속성으로 툴팁을 답니다(`:131`). 동작상 문제는 없지만, "이슈 한 줄" 을 만드는 방법이 사내 표준으로 2가지 존재하는 상태입니다.

## 3. 프로젝트 필터 — 같은 기능이 3벌

| | 홈 대시보드 `:402` | MyCalendarTab `:444` | GraphView `:991` |
|---|---|---|---|
| 컴포넌트 | `DropdownMenuCheckboxItem` | `DropdownMenuItem` + `Check` | `DropdownMenuItem` + `Check` |
| 트리거 | `Button` + 개수 뱃지 | 커스텀 `button` + `FolderOpen` + `n/N` | 동일(커스텀 button) |
| 프로젝트 식별 | **이름 텍스트만** | `ProjectIcon`(icon_prop) | 색상 사각형 + identifier |
| "전체" 시맨틱 | **빈 Set = 전체** | `null` = 전체 | `null` = 전체 |
| 전체선택/해제 | 없음 (해제만) | 있음 | 있음 |
| localStorage 키 | `orbitail_dashboard_filters` (**ws 무관**) | `orbitail_me_cal_projects` (**ws 무관**) | `orbitail_me_graph_projects` (**ws 무관**) |
| 노출 조건 | `length > 1` | `length > 1` | `length > 1` |

### 3-1. 재사용 관점 문제
- 동일 UX가 **구현 3벌**. 시각(아이콘/색/뱃지)도 3종입니다.
- "전체" 의미가 홈만 `빈 Set`, 나머지는 `null` — 훅으로 묶을 때 가장 먼저 충돌하는 지점입니다.
- 홈만 프로젝트 아이콘이 없습니다. `myIssues` 응답에 **`project_icon_prop` 이 이미 포함**돼 있으므로(`backend/apps/issues/serializers.py:25`, `WorkspaceMyIssuesView:1005` 가 `IssueSerializer` 사용) **백엔드 변경 없이** `ProjectIcon` 을 붙일 수 있습니다.

### 3-2. 잠재 버그 (별도 판단 필요)
세 곳 모두 localStorage 키가 **워크스페이스 스코프가 아닙니다.** 워크스페이스 A에서 프로젝트 필터를 걸어둔 채 워크스페이스 B로 이동하면, 저장된 project id가 B의 어떤 이슈와도 매칭되지 않아 **"조건에 맞는 이슈가 없습니다" 로 보입니다**(필터 뱃지는 켜져 있으므로 원인 추적은 가능하지만 사용자 입장에선 데이터 증발로 읽힙니다).
참고로 `TeamCalendarSection:96` 은 `orbitail_team_cal_projects_${teamId}` 로 이미 스코프를 갖고 있습니다 — 팀 캘린더가 올바른 선례입니다.

## 4. 제안 (선택지)

### 4-1. 상태 아이콘 통일

**A안 — 최소 수술 (권장)**
1. `constants/state-icons.tsx` 에 라벨/색 단일 소스를 추가:
   - `STATE_GROUP_LABEL_KEY: Record<StateGroup, string>` (i18n 키)
   - 색은 신규 상수 없이 `var(--state-{group}-border)` 사용
2. 홈에서 `STATE_GROUP_LABEL` / `STATE_GROUP_COLOR` 삭제 → 위 상수 + 토큰 사용
3. `IssueGroup` 에 `group: StateGroup` 필드 추가 → 그룹 헤더를 `getStateIcon(group)` 으로 교체
4. 상태 필터 드롭다운 dot → 동일 아이콘으로 교체
5. `IssueRow` 좌측에 `StateIcon`(`getStateIcon` + `state_detail.color`) 추가 — `IssuePickerDialog` 행 순서와 동일하게 맞춤

> 5번 세부 판단: 홈 좌측은 상태별 그룹이라 아이콘이 중복돼 보일 수 있습니다.
> - **항상 표시(권장)**: 분기 없음 → 코드가 단순, 최근 이슈/recent 페이지 문제가 자동 해결
> - `showState` prop: 중복은 없으나 prop 하나가 늘고 호출부 3곳이 갈라집니다

**B안 — 공용 `IssueListRow` 추출**
홈 `IssueRow` 와 `IssuePickerDialog` 행을 하나로 합칩니다. 재사용성은 최고지만 두 곳의 인터랙션(Link+openIssue vs button+onSelect)과 데이터 타입(`Issue` vs `IssueSearchResult`)이 달라 prop이 늘어납니다. **지금 범위에선 과합니다** — A안 후 세 번째 사용처가 생기면 그때 추출을 권합니다.

**범위 밖(알림만)**: `GraphView:60 STATE_COLOR`, `StatesPage:13 GROUP_LABEL` 도 같은 중복이지만 이번 요청 범위 밖이라 손대지 않았습니다. 원하시면 같은 커밋에 묶겠습니다.

### 4-2. 프로젝트 필터

**A안 — 홈만 시각 통일 (최소)**
홈 드롭다운 항목에 `ProjectIcon value={project_icon_prop} size={10}` 추가. 구현은 여전히 3벌.

**B안 — 공용 컴포넌트 추출 (권장)**
`components/issues/ProjectFilterDropdown.tsx` 신설:
```
props: { projects: {id,name,icon_prop}[], selected: Set<string>|null,
         onChange: (next) => void, align? }
```
- "전체" 시맨틱을 `null` 로 통일 (홈의 빈 Set → null 로 마이그레이션 필요)
- 홈 / MyCalendarTab / GraphView 3곳 교체 → 트리거·전체선택·아이콘까지 한 번에 통일
- GraphView는 `icon_prop` 대신 `projectColorMap` 을 쓰므로, `renderIcon` 옵션 하나로 흡수하거나 GraphView도 `ProjectIcon` 으로 통일할지 결정 필요

**C안 — 훅까지 추출**
B안 + `useProjectFilter(scopeKey)` 로 localStorage 영속 로직까지 공유(ws-scoped 키 자동 적용) → 3-2 버그도 동시 해결. 변경 범위는 가장 넓습니다.
